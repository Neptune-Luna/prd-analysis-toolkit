# 接口覆盖检查表

逐接口使用本检查表。只有需求明确或场景相关的项目才纳入强制结论；其余可作为建议，但要标注依据类型。

## 基础契约

- 接口名称、方法、路径、协议、Content-Type、API 版本是否明确。
- 路径参数、查询参数、请求头、请求体的归属是否明确。
- 请求与响应示例是否与字段表一致。
- 废弃策略、版本兼容和客户端升级策略是否明确。

## 请求字段

- 字段名称、业务含义、类型、格式和单位。
- 必填、可选、条件必填、默认值和缺省语义。
- 字符串长度、数值范围、精度、时间格式、时区。
- 枚举集合、大小写、未知枚举的兼容策略。
- 空字符串、空数组、`null`、字段缺省的差异。
- 字段间依赖、互斥、组合校验和唯一性。
- 批量数量上限、文件大小与类型限制。

## 响应与错误

- 成功响应字段是否足以支撑页面和测试断言。
- 空结果、部分成功、异步受理和最终结果的表达。
- HTTP 状态与业务错误码是否一致、唯一、稳定。
- 参数错误、权限不足、资源不存在、状态冲突、限流、超时、依赖失败是否可区分。
- 错误消息是否可定位且不泄露敏感信息。
- 重试条件、退避策略和可重试标识是否明确。

## 身份、权限与数据范围

- 登录态、令牌、签名或服务身份要求。
- 角色、资源所有权、组织/租户/项目的数据隔离。
- 字段级或操作级权限。
- 越权访问、ID 枚举、伪造租户或用户标识。
- 敏感字段脱敏、加密、审计和保留策略。

## 状态、幂等与并发

- 合法状态和允许的流转方向。
- 非法状态操作对应的错误与恢复方式。
- 幂等键、幂等范围、有效期和相同/不同载荷处理。
- 重复提交、客户端重试、消息重复消费。
- 并发更新的锁、版本号、冲突检测和最终结果。
- 超时、取消、回滚和补偿逻辑。

## 数据一致性与副作用

- 主数据与关联数据的事务边界。
- 部分成功的返回和补偿方案。
- 异步任务、事件、消息、通知和回调。
- 外部依赖失败时的降级、重试、熔断和数据修复。
- 删除、恢复、归档及级联影响。
- 操作日志、审计字段和追踪 ID。

## 查询类接口

- 分页方式、默认页大小、最大页大小和游标失效。
- 过滤条件、模糊/精确匹配、空条件和组合关系。
- 排序字段、默认排序和同值稳定顺序。
- 总数、空列表、已删除/无权限数据的处理。
- 数据量增长时的性能要求。

## 非功能要求

- 延迟、吞吐、并发、可用性和超时指标。
- 限流、配额、缓存和一致性要求。
- 输入注入、重放、越权、敏感信息泄露等安全风险。
- 日志、指标、链路追踪和告警。
- 向后兼容、灰度、回滚和数据迁移。

## 对照测试场景

每个场景都回答：

1. 技术契约是否允许构造该输入和前置状态？
2. 接口是否定义了唯一、可观察的预期结果？
3. 错误和副作用是否可被测试稳定断言？
4. 多接口串联时，状态和数据能否在前后步骤闭环？
5. 场景依赖的隐藏规则是否有需求依据？
