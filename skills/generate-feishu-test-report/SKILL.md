# 生成飞书测试报告

默认中文，直接在飞书文档交付。生成报告不等于执行测试。

## 来源与目标

- 从需求链接解析项目key和工作项ID，读取需求概要、关联缺陷和详情。优先可用连接器，否则使用官方Meegle CLI；云文档可使用已安装的lark-cli。操作见 [飞书工作流](references/feishu-workflow.md)。
- 默认参考样式：https://neptunerobotics.feishu.cn/wiki/ROkqwzAoJiihbSkzk0YcDJ2anSd 。用户提供新模板时优先使用。只参考结构和样式，不复制业务内容、数字或图片。
- 指定目标文档时直接修改；否则搜索同需求标题的既有测试报告，核对需求ID后更新。没有匹配报告则创建，多个候选无法确定时再询问。不要改写参考模板或创建重复报告。
- 状态、级别、归属先读实时数据；用户在当前任务明确纠正的实际状态或责任人优先用于报告。过去某需求的纠正不套用到其他需求。仅更新报告，不修改缺陷工作项。

## 报告格式

正文仅含以下三章，不增加“报告依据”“执行记录”“测试结论”，不另写需求背景或需求明细正文。

### 一、需求说明

1. **需求文档：**需求名称及链接。
2. **测试范围：**按平台、页面或模块简短列出功能改动。只说明功能涉及的地方，不写测试方法、边界组合、待验证说明、证据免责声明或无关的泛化检查。

### 二、缺陷统计

**1.缺陷统计**

- 一句话说明总缺陷数、已修复数和遗留数。关闭记录可写“已修复或关闭”。无需修复、转需求、重复等按实际状态另计，不能算作已修复；各类数量与总数相符。
- 不写状态依据、接口差异、数据来源等附注，不专门列出已修复缺陷明细。
- 按责任人分组，采用模板两层表头：对应人；P0/P1/P2/P3各自的“个数、重启次数”；总缺陷数；冒烟用例覆盖率。
- 级别采用“缺陷评级”，不用需求优先级或空的“严重程度”代替。
- 责任人优先按用户明确指定的人；否则读取经办人／负责人及流转记录。回归阶段当前经办人可能是测试人员，不能自动视为研发责任人。
- **写入缺陷统计前，必须请用户确认各负责人对应的缺陷个数是否正确。** 先展示待确认分组：负责人、P0/P1/P2/P3个数及合计，并单独标出归属未明确的缺陷。用户确认或修正后，再将对应归属和数量写入报告；等待期间继续整理测试范围、遗留影响范围及截图。若用户已对本次同一组缺陷的人员和数量明确确认，不重复询问；新增缺陷或分组、数量变化时重新确认。仅确认状态不等于确认人员归属和数量。
- 用户约定：缺少重启次数填 **0**；缺少冒烟用例覆盖率默认填 **100%**。这是填表默认值，不代表实际运行了冒烟测试，不能据此宣称测试通过。有实际值时用实际值。

**2.遗留缺陷说明**

- 有遗留时列“对应人、P0、P1、P2、P3、总缺陷数”统计表，只列未解决问题的链接、名称及级别。
- 每个问题紧随 **影响范围：**说明平台、页面、部位、触发条件及用户可见影响。可注明已记录的作业ID；不把单例扩大为所有作业，不无依据扩展到数据丢失、PDF错误或计算错误。
- 无遗留写 **遗留的问题：无**；已有遗留表保留时各项置0。

### 三、功能预览

- 不涉及页面改动：仅写 **无**，不用计算示例或预期规则代替。
- 涉及页面改动：到测试环境实际打开对应页面截图，配一句功能说明。不用缺陷历史截图、模板图片、设计稿或生成图片冒充实拍。
- 默认Neptune测试环境为 http://192.168.2.74 ，用户指定环境优先；不因其他域名含test就替换。作业1253只是曾用样例，仅当适合当前功能时使用。
- 遵守当前浏览器工具规则。独立Playwright仅在工具规则允许或用户明确授权时使用；当前任务已有授权持续有效，不重复确认。
- 只读取和打开编辑界面，不保存业务改动、不发布报告、不完成作业。截图后取消未保存编辑。
- 图片存入当前工作区交付目录；检查已加载、功能可见，无登录页或空白遮挡，并用图片查看工具视觉检查。真实权限或浏览器阻塞时如实说明，完成不受阻的报告工作，不伪造实拍。

## 写入与核对

- 先读当前内容和版本，修改最小合理范围。新报告或正文业务整体错误时可重建正文，保留正确标题；后续只改对应段落、表格或图片，不覆盖用户其他编辑。
- 多行富文本用工作区文件传参，按CLI要求读取XML规范。上传后核对图片资源。
- 写后重读核对链接、数量和责任人；默认0和100%符合约定；仅遗留问题有明细和影响范围；无禁止章节；实拍替换旧图。
- 最终简短给报告链接和关键统计。截图操作结果按当前工具要求展示，不把默认覆盖率解释为实测结论。
