## 1. 项目概览

客户需要把潜水员、机器人或其他船体清洗公司产生的检测/清洗报告汇入统一平台，由 AI 按统一标准识别海生物和船漆状况。竞品已开始提供类似开放平台能力，本需求优先级为 P0，当前处于视觉评审阶段。

本期目标是统一管理纳百与非纳百报告并归档到客户船队对应船舶；通过 Dashboard 展示漆况生命周期、风险和作业建议；允许客户在权限范围内微调 AI 识别标准；利用分析结果引导检测/清洗服务转化。

本期包含 Dashboard 首页改版、报告上传及 AI 识别、上传队列、已解析报告列表、报告详情、AI 标准调整与清洗建议展示。不包含纳百报告查看、纳百年度计划业务、平均航速提升、上传拖拽框、上传后的独立文件列表及订单业务；“下单”入口仅跳转未来订单模块。

文档成熟度判定为**粗糙（有需求但粗糙）**：6 个主要页面、3 个状态实体及正常主流程已有描述，但核心算法口径、异常恢复、状态闭环、字段边界、权限快照和跨模块回算尚未闭合，暂不具备直接产出全量测试用例的条件。

## 2. 需求萃取

### 2.1 业务需求

- 统一归集纳百及非纳百检测/清洗报告，并准确归属到客户船队和船舶。
- 基于报告构建船舶漆况生命周期、风险分布、风险趋势、服务建议、节油和减碳视图。
- 支持客户按自身标准微调海生物和油漆损伤识别，并形成客户个性化模型。
- 通过风险和清洗建议促进检测/清洗服务转化。
- 将管理员权限限定为客户全部船舶，普通员工权限限定为自己名下船舶。

### 2.2 用户需求

| 用户 | 核心任务路径 | 权限边界 |
|---|---|---|
| 客户管理员 | 查看全船队 Dashboard → 定位风险/建议船舶 → 上传外部报告 → 检查并修改 AI 摘要 → 查看详情 → 调整本报告或全局 AI 标准 | 可操作客户名下全部船舶 |
| 客户普通员工 | 查看自己名下船舶 → 上传所属船舶报告 → 修改摘要 → 查看详情 → 调整本报告或权限范围内全部报告 | 仅可操作自己名下船舶 |
| 两类用户 | 查看上传队列 → 观察进度 → 暂停/继续或删除 → 解析完成后查看报告；浏览作业日历；导出原报告或跳转订单模块 | 所有读写及全局任务均须受船舶权限约束 |

主要页面流转为：Dashboard 进入船舶详情；上传文件进入上传队列；解析完成后自动移出队列并进入已解析列表；解析摘要或列表进入报告详情；详情进入 AI 标准调整；摘要和详情的下单入口跳转范围外订单模块。

### 2.3 功能需求

#### Dashboard 首页

- 展示船队规模及订阅服务情况。
- 统计未来 45 天可能需要检测/清洗的船舶：清洗候选为最新检测在 3 个月内且海生物等级不低于 R2，或最近检测船漆损伤大于 50% 且 3 个月未清洗；检测候选为超过 6 个月无清洗报告，或超过 3 个月无检测报告。
- 展示最近检测为 poor 且检测后没有进坞行为的船舶。
- 报告覆盖度按“当前船队报告总量（纳百+非纳百）/应有报告数”计算。应有报告数按出坞年限累计为 0、1、3、5、6；覆盖度 `<30%`、`30%~70%`、`>70%` 对应急需、比较需要、充足。
- 展示节油百分比、年度减碳吨数、本年度五类作业数量及港口分布。
- 风险等级为 R0/R1 正常、R2 低风险、R3 中风险、R4 高风险；展示风险分布和近 6 个月 R2+ 船舶趋势。
- 近期建议列表展示船舶、最近作业、服务类型、R2+ 主要风险、建议窗口和理由；R4/R3/R2 窗口分别为 14/45/90 天，默认 7 行，超出分页，整行进入船舶详情。
- 作业日历支持年/月、上/下周期切换，展示检测、清洗、抛光，不展示干船坞；点击日期/周期展示明细和当月时间轴。

#### 报告上传、摘要与列表

- 支持单文件、多文件和文件夹批量上传；页面明确 PDF、DOCX，但“等”所含格式尚未定义。
- 解析摘要展示最近 10 份完成报告并按时间倒序排列；可修改船名、IMO、作业类型、时间、部位和港口。取消不保存并恢复初始状态，确认后保存。
- 船图默认左舷和海生物，可切换左/右舷、底板、螺旋桨、特殊部位及海生物/油漆；特殊部位包含舭龙骨、艏侧推、海底门、舵、艉架、球鼻艏等二级结构。
- 已解析列表支持船名/IMO 搜索，按报告类型、年份、服务类型筛选，按船名和日期排序；每页 10 行，整行进入详情。
- 删除报告需二次确认。删除后不纳入客户报告数据库，但后台保留。

#### 上传队列

- 队列计数为上传一份 `+1`、解析完成一份 `-1`。
- 正常状态为：待上传 → 上传中 → 待解析 → 解析中 → 移出队列并进入已解析列表。
- 上传中可暂停和继续；浏览器关闭等打断后进入可继续上传状态；上传中展示进度条和百分比。
- 所有状态均可删除，删除后应停止后续上传/解析；每页 20 行。

#### 报告详情与 AI 标准调整

- 详情支持返回、导出原报告 PDF、下单检测、摘要编辑、船图浏览和照片查看。
- 报告明细支持 3 线（侧板不分上下）、3 线（侧板分上下）、5 线、10 线四种结构；纳百报告的 5/10 线和上中下分区须与 App 对齐。多图最终交互仍待冻结。
- 海生物和油漆标准默认值分别由全部三板覆盖/损伤比例均值计算，不同分类比例相加；滑条联动环形图、评级和明细表，左宽松、右严格，可重置。
- 未调整时取消/应用不可用；任一滑条变化后按钮启用。取消不保存并恢复初始值。
- “应用到本报告”仅影响当前报告且不触发个性化；“应用到全部报告”影响客户账号下操作者有权限船舶的全部报告并触发模型个性化。
- 调整记录仅展示实际调整项，记录宽松/严格、偏移值、应用范围、操作者邮箱和分钟级时间；全局应用带“全局操作”标签，每页 10 条。

### 2.4 非功能需求

**需求已明确：**

- 权限与隔离：管理员访问客户全部船舶，普通员工仅访问自己名下船舶；全局应用不得越权。
- 可恢复性：浏览器关闭等导致上传中断后应可续传。
- 数据持久化：客户侧删除后业务库不再计入，后台仍保留。
- 可审计性：AI 调整记录需保留实际调整项、范围、全局标记、操作者和提交时间。
- 跨端一致性：纳百报告 5/10 线布局及上中下分区与 App 保持一致。

**由测试分析推导、待确认：**

- 上传需服务端校验扩展名、MIME 和内容，并隔离损坏或恶意文件。
- 批量上传、解析、导出、删除和全局模型应用需提供状态、失败原因、重试与幂等反馈。
- 摘要编辑和全局配置需具备版本冲突处理、审计及权限变化策略。
- Dashboard 派生数据需统一快照、同船去重、缓存失效和补录/编辑/删除后的回算规则。
- 普通查询 `<500ms`、Dashboard 首屏 `<3s`、搜索 `<300ms`、导出 `<30s`、长操作 `>3s` 展示进度仅为经验讨论基线，**不是当前已确认需求**。

## 3. 分析与评价

### 3.1 完整性

正常主链“风险发现 → 上传 → AI 解析 → 列表/详情 → 调整 AI 标准”基本完整；管理员/员工权限、批量上传、暂停续传、筛选排序、船图切换及本报告/全部报告两种应用范围已有描述。

主要缺口集中在上传/解析失败、超时、4xx/5xx、重复提交、并发编辑、会话过期、多端操作、空数据、全局任务部分失败和删除恢复。Dashboard、解析摘要、已解析列表、上传队列、报告详情、调整记录六个页面均缺少完整空态；报告照片无图/加载失败、AI 无识别结果等局部空态也未定义。

### 3.2 一致性

- 解析摘要和报告详情的字段、取消/确认主逻辑一致，但是否复用同一实体、校验和保存接口尚未明确。
- 上传时间精确到分钟、作业时间精确到天、筛选使用年份，时间粒度和时区口径未统一。
- 本期明确不做纳百年度计划业务，但服务类型筛选仍含“纳百年度计划”，范围存在冲突。
- “报告类型/作业类型/服务类型”“全部报告/全局操作/模型个性化”之间的字段或术语关系未定义。
- 摘要入口写“下单检测/清洗”，详情入口写“下单检测”，入口文案不一致。

### 3.3 合理性

- 首页只统计未来 45 天，而 R2 建议窗口为 90 天，核心展示口径冲突。
- “近 3 个月检测且 R2+”可能排除更早但仍处于高风险的船舶，业务合理性需产品确认。
- 报告覆盖度第一年应有报告数为 0，存在除零问题；每次进出坞不清零与生命周期目标存在口径张力。
- 风险分布一处描述为 R2+ 占船队比例，另一处要求 R0/R1、R2、R3、R4 四档分布，算法不闭合。
- 删除、保存和 AI 应用缺少 loading、成功/失败及回滚反馈；列表长文本缺少截断和完整内容入口；权限入口的隐藏/禁用规则未定义。
- 摘要与详情重复编辑相同字段，若不复用规则和接口，易产生双入口数据漂移。

### 3.4 量化性

已明确的量化项包括：未来 45 天、R4/14 天、R3/45 天、R2/90 天、3/6 个月时间条件、损伤 `>50%`、覆盖度三档、近 6 个月趋势、建议列表 7 行、摘要最近 10 份、报告列表 10 行/页、队列 20 行/页及调整记录 10 条/页。

仍需量化：上传格式白名单、单文件/单批大小和数量、目录深度、并发数；上传进度刷新频率；AI 滑条上下限、步长、精度及缺板/超 100% 算法；全局任务规模和 SLA；删除保留期；模型版本、数据窗、刷新周期和精度；日期边界、时区、同值排序和分页越界规则。

### 3.5 逻辑闭环

| 实体 | 已定义状态/行为 | 缺失闭环 |
|---|---|---|
| 上传任务 | 待上传、上传中、暂停/继续、待解析、解析中、完成移出；所有状态可删除 | 上传/解析失败、重试中、取消/删除中、删除失败、超时；失败和删除对队列计数的影响 |
| 报告 | 解析完成进入列表；可编辑、导出；客户侧删除、后台保留 | 解析失败、待人工确认、保存中/失败、恢复中、永久删除及恢复期限 |
| AI 配置 | 初始、已调整未应用、应用到本报告、应用到全部报告 | 应用中、部分失败、版本冲突、撤销/回滚、历史版本及权限变化 |

页面主链无明确死路，但船舶详情和未来订单为范围外目标，返回链路未验证；报告详情从摘要和列表两个入口进入，其“返回”目标及筛选/页码保留规则未定义。

## 4. 澄清清单

### 4.1 文档成熟度与优先级

共识别 46 项澄清：🔴阻塞级 14 项、🟡影响覆盖级 21 项、🟢优化建议级 11 项。建议先完成下列阻塞项并回填需求，再设计全量用例。

### 4.2 🔴 阻塞级（14 项）

| 类别 | 待澄清问题 | 建议确认结论 |
|---|---|---|
| 异常分支 | 上传/解析遇到失败、超时、4xx/5xx 后进入什么状态，如何提示、重试和处理已上传数据？ | 给出失败状态、错误提示、自动/手动重试、可操作项及队列计数变化 |
| 异常分支 | “应用到全部报告”超时或部分失败时，是全回滚还是部分成功？ | 明确原子性、成功/失败清单、重试、最终状态及记录落库 |
| 异常分支 | 多账号并发编辑同一摘要或全局标准时如何处理？ | 明确最后写入、乐观锁或互斥策略及冲突恢复方式 |
| 边界值 | 未来 45 天统计是否包含 R2 的 46~90 天？ | 统一首页统计与 R2 建议窗口口径 |
| 边界值 | 覆盖度分母为 0 时如何展示，恰好 30%/70% 属于哪档？ | 给出零分母和闭区间规则 |
| 边界值 | 上传允许哪些格式及多大规模？ | 给出扩展名/MIME 白名单、单文件/单批大小、数量、目录深度、并发及超限处理 |
| 边界值 | AI 滑条和三板算法边界是什么？ | 明确最小/最大、步长、单位、精度、缺板、异常值及比例超过 100% 的公式 |
| 状态机 | 上传任务完整状态和转换是什么？ | 补全失败、重试、取消/删除中、删除失败、完成、超时、操作权限和计数 |
| 状态机 | AI 标准应用后能否撤销或回滚？ | 补全应用中/失败/冲突/撤销/历史版本及恢复目标版本 |
| 状态机 | 客户侧删除的报告能否恢复，何时永久删除？ | 明确恢复角色、入口、期限、恢复结果和永久清理策略 |
| 隐性依赖 | 全局应用是否重算全部历史报告，处理中新增报告是否纳入？ | 定义任务范围快照、生效时机及处理中各页面展示旧值还是新值 |
| 隐性依赖 | 管理员/普通员工“全部报告”的权限范围及权限变化如何处理？ | 明确船舶/报告范围、执行中权限变化和历史记录可见性 |
| 隐性依赖 | 多份报告下风险分布、趋势和建议取哪份，是否按船去重和回算？ | 定义统一快照、去重、最近报告、补录/编辑回算规则 |
| 隐性依赖 | 本期不做年度计划，但筛选为何保留该服务类型？ | 明确其只是历史标签还是依赖年度计划业务数据 |

### 4.3 🟡 影响覆盖级

- 补齐列表、详情、导出、删除的超时/失败/重试/回滚，以及提交防重和服务端幂等。
- 明确断网、刷新、会话过期时上传进度和未保存表单的保留、重新登录及原路由恢复。
- 定义快速切换船图、日历和筛选时的请求竞态处理。
- 为六个主要页面补齐首次空、筛选空、权限空及局部无识别结果状态。
- 明确恶意、损坏、重复、扩展名与 MIME 不一致文件及批量部分失败策略。
- 补齐船名、IMO、作业类型/部位/港口、日期时区、布尔条件、趋势月份、分页、超长文本和特殊字符边界。
- 明确中间态超时、处理中删除的服务端终止和资源清理、重置/取消/应用基线、摘要保存中/失败状态。
- 明确删除或编辑报告对 Dashboard、AI 模型、归船、列表和导出的同步/回算影响，以及节油/减碳模型口径和完整审计规则。

### 4.4 🟢 优化建议级

- 量化 loading、进度、超时和成功提示；确认多端并发策略。
- 明确上传进度刷新频率、所有列表稳定排序及正式性能验收指标。
- 确定详情返回目标和来源页状态保留、多图浏览最终交互、解析中视觉及自动刷新时机。
- 统一类型字段和全局应用术语；定义订单跳转参数、无权限降级和调整记录跨报告去重。

## 5. 评审意见

### 5.1 评审结论

需求类型判定为**新需求**。业务主链和本期范围基本可识别，但当前版本不建议直接冻结测试范围或进入全量用例设计。至少应先解决 45/90 天、覆盖度零分母、上传规格、AI 算法边界、全局应用一致性、权限快照、删除生命周期和 Dashboard 去重回算八类核心问题。

### 5.2 关键评审意见

1. 先确定本期首要成功指标：报告归档量、风险识别覆盖率或服务转化率，避免功能完成但无法验收业务价值。
2. 统一 Dashboard 所有统计的快照、去重、最近报告和回算口径，确保风险分布、趋势、建议和覆盖度数字一致。
3. 为上传、解析、报告和 AI 配置建立完整状态转换表，覆盖失败、超时、重试、删除中、冲突、撤销和回滚。
4. “应用到全部报告”应按批任务设计，明确范围快照、原子性、幂等、进度、失败清单、历史重算和审计。
5. 摘要与详情编辑应尽量复用同一实体、校验和保存接口，并处理并发版本冲突。
6. 客户侧删除应采用可审计的软删除生命周期，并明确对统计、模型、缓存、导出和永久清理的影响。
7. 六个页面需补齐空态、错误态、提交反馈和无权限状态；解析中视觉和多图交互必须在验收前冻结。
8. 性能数值目前仅为经验建议，须结合数据规模、并发和 P95 由产品/开发确认后才能进入验收标准。

### 5.3 需要向产品经理确认

- 本期首要成功指标和验收目标是什么？
- 45 天统计与 R2 90 天窗口如何统一，覆盖度零分母及 30%/70% 边界如何处理？
- 建议检测/清洗条件的完整布尔表达式是什么，损伤等于 50% 和无历史报告如何判断？
- 同船多报告时各 Dashboard 指标取值、去重和历史回算口径是什么？
- 全局 AI 应用的历史范围、任务范围快照、部分失败和撤销策略是什么？
- 删除报告是否可恢复、谁能恢复、期限多久、何时永久删除？
- 正式上传规格、核心字段校验和六类页面空态何时冻结？
- 年度计划筛选项是否只是历史标签；订单跳转需携带什么参数并如何降级？

### 5.4 需要向开发确认

- 上传、解析、报告、AI 配置完整状态枚举和转换表如何设计？
- 超时、4xx/5xx、重试、删除处理中如何保证幂等、计数和资源清理一致？
- 全局应用采用同步还是异步，任务规模、批大小、进度、超时、重试和回滚如何实现？
- 并发摘要编辑和全局配置采用乐观锁、互斥还是最后写入？
- 文件类型/内容/恶意检测、重复文件和批量部分失败如何处理？
- 船舶权限变化发生在批任务执行中时按提交快照还是实时鉴权？
- Dashboard 使用实时查询、缓存还是离线任务，数据变更后多久达到一致？
- 会话过期、断网、刷新和快速切换时，上传会话、草稿、任务和请求竞态如何恢复？

### 5.5 建议回归范围

| 关联点 | 建议回归范围 |
|---|---|
| 报告归船与摘要字段修改 | 管理员/员工数据隔离、IMO/船名匹配、权限新增移除、错误归船修正 |
| Dashboard 派生统计 | 纳百/非纳百合并、同船去重、补录/编辑/删除回算、跨图表一致性 |
| 下单入口 | 参数携带、鉴权、目标不可用、返回链路；不扩展订单内部业务 |
| 报告详情布局 | 3 线分/不分上下、5/10 线、特殊部位、照片映射及与 App 一致性 |
| 全局 AI 个性化 | 权限范围、模型版本、历史重算、部分失败/回滚、调整记录与结果一致性 |

### 5.6 评审会发言稿速查

1. 首页口径有硬冲突：统计未来 45 天，但 R2 建议窗口是 90 天，请明确第 46~90 天是否进入首页。
2. 覆盖度算法未闭合：分母为 0 怎么展示，30% 和 70% 分别归哪档。
3. 上传和解析只有成功路径，请补全失败、超时、重试、删除中和删除失败状态。
4. “应用到全部报告”必须明确原子性、范围快照、失败清单、重试、版本及撤销。
5. 报告删除需要补恢复期限、永久删除、审计，以及 Dashboard 和模型何时排除。
6. 两个入口编辑同一摘要，请确认是否复用实体、校验、接口，并避免并发静默覆盖。
7. 上传规格需给正式数字；空态、解析中和多图交互需冻结为验收依据。
8. 性能数字暂为经验建议，确认数据规模、并发和 P95 后才能写入验收标准。
